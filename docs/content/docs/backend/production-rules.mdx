# 短剧制作执行规范

新建短剧任务使用一份版本化规则，按阶段和输出类型组合。规范用于减少已知不合适的制作要求、上下文混入及参数不一致；它不是上游审核通过保证，也不能消除超时、服务故障或模型输出不完整。

## 阶段规则

| 阶段 | 执行要求 |
| --- | --- |
| 剧情与章节 | 保持角色年龄身份、集数时长、剧情因果和题材风格；复杂或敏感场面使用可制作的非露骨叙事，不将规范写入对白。 |
| 资产拆分 | 忠实保留逐集事实和证据，跨集归并同一主体；外观、声音、变体和依据分开。危险物件只设计无功能影视道具的外观，不请求内部机构、拆装或制造操作。 |
| 分镜脚本 | 沿用稳定镜头与资产编号；每镜头明确动作、调度与衔接，首尾帧保持人物状态、空间和光线连续。 |
| 配音与声音 | 台词、说话人、表演参数分别存放；禁止把制作规范拼入实际朗读文本。模型支持的表演字段沿用现有协议。 |
| 视频生成 | 只使用模型已声明支持的时长、参考帧、分辨率与声音能力；不默默换模型或丢弃参考图。 |
| 剪辑与后期 | 使用真实素材版本，区分画面、对白、音乐、音效和字幕；不把建议冒充已完成渲染。 |
| 成片质检 | 只报告实际看过、听过、测量过的内容；缺少证据标为待验收，不伪造审核结论。 |
| 导出交付 | 核对实际文件、版本、规格及缺件；封面预告同样遵循项目风格与表现边界，不擅自发布。 |

通用规则保留正常戏剧冲突，禁止通过改名、暗语或编码绕过模型审核。原文事实与证据保持忠实，面向媒体生成的具体表现另行约束；规范不会批量重写已经保存的正文或资产。

## 接入与版本

- 唯一规则源为 `backend/internal/productionrules/rules.json`；Go 通过嵌入加载，前端使用提交到仓库的 `web/src/lib/production-rules.generated.ts`，部署时不依赖访问后端源码目录。
- 修改规则时同步提升 JSON 版本和 Go `Version`，在 `web/` 执行 `bun run generate:production-rules`。前端行为测试核对两端目录一致，并检查所有阶段与步骤都有规则。
- 故事创作、流程文稿、资产设定板与分镜图片在提示词组装时接入；长度和分批判断包含规范开销。制作 Agent 的初始请求及恢复请求共用现行规范；批量任务的中间与最终请求分别接入，确定性任务标识包含有效规则，避免新请求复用旧规范结果。
- 任务入口仅识别明确的短剧来源：`canvas-short-drama-workflow`、`canvas-story-development`、`canvas-workflow-batch-child`。来源元数据用于选择规范，不代表权限或计费豁免。普通创作任务不因此被重写。
- `audio` 合成正文保持原样。声音规范在台词准备与声音设计文稿中生效，不向不支持的供应商强塞 `instructions` 参数。
- 已保存任务不自动重提或改写。原样重试仍受原有提交状态、审核失败和费用核对保护；用户主动调整后提交的新任务使用当前规则，并保留原任务关联。
- 未标注阶段的历史内部批次保留原任务标识和已完成子任务，避免恢复时重复调用。制作 Agent 的共享事实仍按原解析版本、来源与模型身份复用；制作规范约束后续设计，不为更新表现方式重新提取不变的原文事实。

## 能力与计费

规范不能替代强校验。模型类型、输入长度、图片规格、参考数量、视频时长等继续以已配置模型能力和实际协议校验为准；不硬编码猜测出的厂家限制，不通过关键词批量拦截正常剧情。

新请求在正常计费预留前完成规则处理及原有能力校验；计费、扣费、退款、权限、资源归属和节点绑定保持原链路。规范带来的真实输入用量按原有规则统计，不增加任务调用次数或积分上限。

本轮补齐图片任务对已有 `references.promptMaxChars` 配置的校验：按 Unicode 字符统计完整提示词，常规模型包含实际拼接的系统提示词，图片工作流按实际正文及已声明配置校验。前端复用模型长度检查，在准备上传和创建任务前提示；后端在入队、预扣之前再次检查。Grok 特定模型原有 UTF-8 字节限制仍独立保留。不会自动截断或丢弃项目内容来满足长度。

## 验证边界

本地测试使用隔离数据与模拟响应，检查阶段覆盖、重复注入、结构化输出要求、配音正文、共享结果隔离及正常计费边界。真实上游审核、成图质量、声音效果和具体模型限制仍需在实际项目中人工验收。
