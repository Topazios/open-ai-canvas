# 短剧制作执行规范

## 制作方案并发与分组

### 防止末步空转

模型调用成功不等于制作有进展。防空转按相同持久检查点下重复的读取参数、执行成功回执与无工具说明识别；不同分页、来源、版本或新保存成果不计为同一循环。纠偏后仍未推进时停止并保留继续入口，不以累计调用次数或积分作为结束依据。

任务成功后的输入精简保留内部 `productionCheckpoint`、`productionRecovery`、`productionRequiredTool`，否则下一轮无法识别重复读取。公共任务输出仍过滤这些内部字段及原始模型输入；原账务流程不变。旧记录已删除的检查点不伪造恢复，新请求按新版合同记录。

全部资产完成后的 `generation` 使用当前公共规范及资产索引，工具仅开放 `production_submit` 并要求提交，不再遍历全部档案。该文稿制定共用引用、状态衔接、验收与返修规则，具体资产参数以已保存档案为权威。仅输出说明、再次查询或未提交指定文稿时保留进度并停止，不用系统伪造正文。保存后系统直接发起既有完整性检查，检查通过才结束；不再额外付费询问模型是否检查或结束。人工编辑保护或缺失文稿仍会阻止完成。

### 旧八项规范的前置整合

保留四份共用文稿和系统资产总表。旧规范的八项职责必须覆盖，但不再额外创建八份文档。参考的是职责与内容结构；其他项目的正文、人物、声音、风格和世界设定不能成为当前项目的事实依据。

| 原制作规范 | 前置归属 | 影响制作质量的必要内容 |
| --- | --- | --- |
| 世界观与规则 | 故事总纲 | 年代地域、组织术语、规则触发、范围、限制代价、失效条件和可视化表达；现实项目不强加超自然能力。 |
| 人物关系与时间线 | 故事总纲 | 身份别名与年龄阶段、关系变化原因、知情范围、实际时间与叙事顺序、物件归属和不可逆事件。 |
| 全局视觉风格 | 视觉与美术规范 | 媒介质感、色彩、光源、视觉母题与风格禁区，落实到可见特征。 |
| 美术与服化道 | 视觉与美术规范 | 人物轮廓服化、建筑空间、道具材质尺度、特效边界；各类参考图的视角、面板顺序、背景和主体比例统一。 |
| 摄影与剪辑 | 导演与视听规范 | 叙事视角、开场与结尾节奏、轴线视线、机位运镜使用条件、动作匹配、反应镜头和转场依据。 |
| 表演与配音 | 导演与视听规范＋人物档案 | 共用表演尺度、对白旁白用途、语言口音、语速停顿与口型同步；具体声线由人物档案唯一维护。 |
| 音乐与环境声音 | 导演与视听规范＋独立声音档案 | 主题用途与进出点、环境声层次空间、标志音和同步、对白避让及静默；独立复用声音才建资产。 |
| 生成与一致性约束 | 生成与一致性规范 | 输入输出和依赖、编码与变体、参考与提示词、状态链、缺陷判定、局部返修、版本及交付核对。 |

每条关键规则应说明“不变项、变化条件、检查方法”。省去重复抄写全局参数、无依据的电影感描述、提前编造的完整镜头表和未知模型参数。生成规范最终归纳已经完成的设计；视觉与导演规范并行时只依赖总纲、清单和项目约束，不能相互等待或声称已经读取另一份未完成文稿。

执行要求集中在 `production_plan_requirements.go`，按当前文稿字段注入 `production_submit` 工具 schema，串行和并发使用同一来源，不将所有文稿规则重复放入上下文。标题和持久字段保持兼容，不批量判定旧回执失效。新提交的整字段占位文本会得到字段级修正提示；合理的不适用说明可以保存。机器检查不以关键词命中代替剧情与媒体质量验收，也不宣称已看过尚未生成的媒体。已保存文稿需要主动修订或新建版本才会按增强要求补全，不自动覆盖原稿。

前置方案保持“总纲 → 完整清单 → 美术/导演规范 → 资产档案 → 生成连续性规范 → 检查”的依赖顺序。美术与导演规范可以并发；两份规范有效后，独立资产最多同时执行 3 项，`dependsOn` 指定的前置档案必须先保存且版本有效。最终规范等待所有资产完成。实际并发仍受平台 Worker、渠道并发与余额约束，不绕过正常计费、扣费或上游状态核对。

在途模型任务及依赖版本持久化，恢复复用原任务身份；模型调用可以并行，结果逐项事务写入。账号同时运行的任务已满时等待空位，不因队列暂满将整轮判失败。暂停后不再派发新调用，允许已有响应保存；取消会清理全部关联调用。单项输出错误沿用有限纠偏重试，失败后可继续该项，已完成项保留；没有新增整个制作任务的累计调用或积分限制。存储错误、前置变更或删除不触发模型重生成。

公共容器保存四份共用文稿及系统资产总表，人物、场景、道具、特殊资产和独立声音按有无实际资产分别创建独立容器。只连接公共方案与分类容器，分类内节点不逐条连接。每组从第一个位置开始按三列、固定宽高和间隔排列，隐藏任务锚点不占格。运行任务进入模型边界时整理尚未分组的旧产物，保留节点 ID、正文、资产编码并同步重算依赖回执；人工修改、移动或删除的产物不自动覆盖。

集纲、正文、资产校核和参考图读取同一方案关联的分类容器；分镜输入仍保持对应集范围。分组不是新版本，也不复制资产。真实耗时取决于渠道吞吐和模型响应，不承诺固定倍数或几分钟完成；质量与实际页面交互仍需人工验收。

新建短剧任务使用一份版本化规则，按阶段和输出类型组合。规范用于减少已知不合适的制作要求、上下文混入及参数不一致；它不是上游审核通过保证，也不能消除超时、服务故障或模型输出不完整。

## 阶段规则

### 资产参考图输入边界

`assets/image` 使用独立的精简视觉规则，不叠加文本资产拆解、剧情因果、配音或交付规范。前后端共用规则目录；应用时替换提示词开头的旧同作用域 v1 规则块，正文中的引用文本和其他作用域不改写。

前端按已知文稿结构选择对应资产的可见设计，以及项目视觉设定、画风和本类美术要求。资产原稿、稳定编码、来源版本、参考图和显式变体引用仍保留；不把资产原始生成提示词、剧情表演和全部连续性规则重复复制进生图请求。未知自由文本和用户明确补充保持原意，缺少必要外观材料则报错，不伪造设计。

新设定板保存系统生成提示词的指纹。失败重试只在指纹证明未手动修改时重新组装；旧任务没有指纹则保留原输入，主动自动调整或新建生图使用当前筛选规则。已返回媒体的下载、保存恢复沿用原任务，不因此重新调用模型。历史任务和账务记录不批量改写。

| 阶段 | 执行要求 |
| --- | --- |
| 剧情与章节 | 保持角色年龄身份、集数时长、剧情因果和题材风格；复杂或敏感场面使用可制作的非露骨叙事，不将规范写入对白。 |
| 资产拆分 | 忠实保留逐集事实和证据，跨集归并同一主体；外观、声音、变体和依据分开。危险物件只设计无功能影视道具的外观，不请求内部机构、拆装或制造操作。 |
| 分镜脚本 | 沿用稳定镜头与资产编号；每镜头明确动作、调度与衔接，首尾帧保持人物状态、空间和光线连续。 |
| 配音与声音 | 台词、说话人、表演参数分别存放；禁止把制作规范拼入实际朗读文本。模型支持的表演字段沿用现有协议。 |
| 视频生成 | 只使用模型已声明支持的时长、参考帧、分辨率与声音能力；不默默换模型或丢弃参考图。 |
| 剪辑与后期 | 使用真实素材版本，区分画面、对白、音乐、音效和字幕；不把建议冒充已完成渲染。 |
| 成片质检 | 只报告实际看过、听过、测量过的内容；缺少证据标为待验收，不伪造审核结论。 |
| 导出交付 | 核对实际文件、版本、规格及缺件；封面预告同样遵循项目风格与表现边界，不擅自发布。 |

通用规则保留正常戏剧冲突，禁止通过改名、暗语或编码绕过模型审核。原文事实与证据保持忠实，面向媒体生成的具体表现另行约束；规范不会批量重写已经保存的正文或资产。

## 接入与版本

### 前置项目制作方案与资产身份

新建 `story.plan` 使用 `shortDrama.planVersion=2`。制作 Agent 按持久成果推进：读取选题与全局设定 → 故事总纲与世界规则 → 资产清单与编码 → 视觉美术、导演视听规范 → 按设计依赖逐项保存资产档案 → 生成与连续性规范 → 完成检查。新版系统指令独立选择，不叠加旧版相冲突的顺序。运行工具由任务类型决定，制作方案不能调用分镜或正文事实提取工具。

资产清单分批登记，`complete=true` 前必须核对五类资产并拒绝未知或循环设计依赖；没有某类时填写理由。每项登记剧情功能 `purpose`、计划篇章或集段 `plannedRange`，准确集次尚未确定时 `episodes` 可为空。完成登记后固定本版范围，系统自动保存“资产总表与编码”文本节点，避免再次调用模型抄写索引。正常重试复用清单、编码和节点；总纲修订会使相关下游文稿需要重新核对。

四份模型共用文稿与系统清单通过 `planSection` 标识。模板定义在 `production_plan_document.go`，当前待写文稿的字段直接进入 `production_submit` 工具 schema，服务端校验缺项、重复标题、未知字段及本版 `@资产编码` 引用。文稿记录 `planDependencies` 输入版本；缺项补写沿用原节点和 `expectedHash`，不覆盖人工修改或复活删除节点。

| 文稿类型 | 主要必填内容 |
| --- | --- |
| 故事总纲 | 定位、命题、主角目标动机及代价、世界和运行规则、冲突升级、故事因果、篇章集段、人物关系弧光、结局安排、伏笔及时间线；开放结局遵循全局设定。 |
| 视觉规范 | 风格、色彩、光线、构图、人物服化、建筑空间、道具材质、特效、参考图版式及视觉一致性。 |
| 导演规范 | 叙事视角、节奏、调度、摄影、剪辑、表演、对白旁白、配音、音乐、环境声、音效和声画关系。 |
| 人物 | 身份功能、性格、动机、经历、关系弧光、外观服化、动作表演、状态变体；声音另有音色、音域、语速、口音、表演边界和配音提示词字段。 |
| 场景 | 剧情用途、时代地理、布局尺度、出入口、邻接关系、材质、光源、机位边界、状态变体和环境声。 |
| 道具 | 剧情用途、外观尺寸材质、归属交接、影视表现与外观状态、人物交互、状态链和声音。 |
| 特殊资产 | 性质功能、形态、触发条件、能力范围、限制代价、视听表现及状态变化。 |
| 独立声音 | 类别、关联资产编码、音色节奏、情绪、空间感、进入退出、循环、混音和对白避让；不重复定义人物声线。 |
| 生成规范 | 生成顺序、身份及参考图引用、提示词组成、图像视频音频要求、状态衔接、质检、局部返修及版本连续性；不虚构模型接口能力。 |

共同要求为来源与设计区分、适用的生成提示词和禁止变化、连续性及未定事项。字段确实不适用时需说明原因；有字段不代表语义质量通过。缺项文稿按当前模板增补，已完成历史文稿不批量改写。机器检查负责结构、版本、依赖及登记清单覆盖，剧情合理性与制作质量仍待人工验收。

详情显示当前阶段、当前文稿和有效产物数；清单完成前不展示误导性的最终总数。工具错配在再次调用模型前停止，保留产物和恢复入口，已完成的上游调用仍按原链路计费。来源变化或人工编辑保护不会伪报成功。

资产身份保存在 `shortDrama.assetIdentity` 及持久任务清单中，包含不可变 `id`、可读 `code`、`kind`。服务端使用现有 `id_sequences` 表分配 CHR-0001、SCN-0001、PRP-0001、SPC-0001、AUD-0001；同一用户画布内按类型递增，删除节点或任务后不回收编号。不同画布可使用相同可读编码，内部 ID 仍不同。登记重试复用同一身份，事务失败不会留下半次登记；修改另一版方案时只有显式沿用已有编码才复用身份，不按名称自动合并。状态变体拥有 `CHR-0001-V0001` 等独立引用编码，与资产身份及节点版本分开维护。

第二阶段的新任务统一为 `assets.reconcile`：每集正文解析一次，跨集核对五类资产、实际出场、变化与新增项。既有计划资产按需读取，修订前必须读取原档案，沿用身份与设计；新增资产由服务端分配编码。用户编辑保护、来源签名、检查点、计费与扣费继续使用原机制，不新增数据库迁移。完成任务不代表通过人工语义审核。历史分类任务保留原合同及进度展示，不批量改写旧资产编号。

人物、场景、道具及特殊资产参考图可以直接选择完整的前置方案容器，不必等待正文。参考图沿用资产身份，仍由生图模型实际生成；文稿不计为媒体完成。工作流生成设置支持输入 `@编码` 选择来源链中的资产及变体，组装实际描述与已选择的参考图；编码不存在、同一编码身份冲突或同一步骤混入多个版本时阻止提交，不跨项目查找同名资产。单集分镜只读取该集正文与共用规则，排除方案中的资产档案和全剧故事文稿，资产绑定在后续镜头提示词步骤完成。

旧单篇或旧版分组方案继续可读，但不会自动补造前置规范与编码。使用完整新流程时，从已采用选题生成另一版项目制作方案。声音资产目前交付设计档案，实际配音、视频、剪辑和导出仍以各自已有执行能力为准。

### 分镜与长任务检查点

`direction.shots` 使用既有制作 Agent。服务端先保存同版本制作约束简报，再读取一集完整正文建立场次/动作段规划；随后每次只提交当前场的镜头批次。原文按非空行编号，超长段保留句子边界，模型决定场次范围；不按固定字符数机械生成互不相关的分镜。

场次清单和已保存镜头位于 `production_agent_jobs.manifest_json.storyboard`，包含协议版本、简报引用、整集时长、场次、原文范围、入场/出场状态、镜头和校验哈希。来源页仍绑定原节点与模型版本，资产目录通过稳定节点 ID 关联。简报存在既有 `production_agent_pages`，与事实页使用不同的标识前缀。没有新增表或迁移。

`production_storyboard_context/brief/plan/submit/read/review/reset` 分别负责检查点、简报、规划、增量写入、按需读取、整集检查和当前场修复。每批最多 8 个镜头用于控制单次输出体积；任务没有累计调用次数或积分上限，模型计费照常。完成检查要求场次齐全、引用覆盖、编号/资产/时长有效和整集模型校验完成；不等同人工审核或画面实际生成。

资产分解继续一集一页提取、跨集归并；模型请求在成功保存检查点后移除旧正文会话历史，保留制作约束和当前工具组。运行日志和已保存事实不删除。分镜按集共享相同来源版本的制作简报，场次按顺序执行保证衔接，各集仍由现有渠道并发策略调度；未新增无限并发。

旧普通文本任务保持原任务及账单，不能自动改写成新流程或重提。新建分镜使用新执行方式；失败的制作 Agent 可在节点详情继续原运行。所有来源版本校验、人工编辑保护、节点删除取消与扣费保护继续生效。

分镜简报还包含目标节点声明的上游制作方案和规范来源，按版本纳入清单。逐场执行降低重复输入，但整集规划仍需读取一集完整正文，简报首次生成仍需读取相关规范；极端超长单集尚未增加按模型上下文窗口自适应规划。具体完成时间、对白语义覆盖与跨场制作质量需真实模型验收，不能把结构校验通过等同于质量和耗时达标。

- 唯一规则源为 `backend/internal/productionrules/rules.json`；Go 通过嵌入加载，前端使用提交到仓库的 `web/src/lib/production-rules.generated.ts`，部署时不依赖访问后端源码目录。
- 修改规则时同步提升 JSON 版本和 Go `Version`，在 `web/` 执行 `bun run generate:production-rules`。前端行为测试核对两端目录一致，并检查所有阶段与步骤都有规则。
- 故事创作、流程文稿、资产设定板与分镜图片在提示词组装时接入；长度和分批判断包含规范开销。制作 Agent 的初始请求及恢复请求共用现行规范；批量任务的中间与最终请求分别接入，确定性任务标识包含有效规则，避免新请求复用旧规范结果。
- 任务入口仅识别明确的短剧来源：`canvas-short-drama-workflow`、`canvas-story-development`、`canvas-workflow-batch-child`。来源元数据用于选择规范，不代表权限或计费豁免。普通创作任务不因此被重写。
- `audio` 合成正文保持原样。声音规范在台词准备与声音设计文稿中生效，不向不支持的供应商强塞 `instructions` 参数。
- 已保存任务不自动重提或改写。原样重试仍受原有提交状态、审核失败和费用核对保护；用户主动调整后提交的新任务使用当前规则，并保留原任务关联。
- 未标注阶段的历史内部批次保留原任务标识和已完成子任务，避免恢复时重复调用。制作 Agent 的共享事实仍按原解析版本、来源与模型身份复用；制作规范约束后续设计，不为更新表现方式重新提取不变的原文事实。

## 能力与计费

规范不能替代强校验。模型类型、输入长度、图片规格、参考数量、视频时长等继续以已配置模型能力和实际协议校验为准；不硬编码猜测出的厂家限制，不通过关键词批量拦截正常剧情。

新请求在正常计费预留前完成规则处理及原有能力校验；计费、扣费、退款、权限、资源归属和节点绑定保持原链路。规范带来的真实输入用量按原有规则统计，不增加任务调用次数或积分上限。

本轮补齐图片任务对已有 `references.promptMaxChars` 配置的校验：按 Unicode 字符统计完整提示词，常规模型包含实际拼接的系统提示词，图片工作流按实际正文及已声明配置校验。前端复用模型长度检查，在准备上传和创建任务前提示；后端在入队、预扣之前再次检查。Grok 特定模型原有 UTF-8 字节限制仍独立保留。不会自动截断或丢弃项目内容来满足长度。

## 验证边界

本地测试使用隔离数据与模拟响应，检查阶段覆盖、重复注入、结构化输出要求、配音正文、共享结果隔离及正常计费边界。真实上游审核、成图质量、声音效果和具体模型限制仍需在实际项目中人工验收。
