# 本地开发

## Compose 公网资源地址

`docker-compose.yml`、`docker-compose.dev.yml`、`docker-compose.local.yml`、`docker-compose.server.yml` 和 `docker-compose.deploy.yml` 均将 `.env` 中的 `CANVAS_PUBLIC_BASE_URL` 传入后端。使用本地文件存储且上游模型需要读取参考素材时，将它设为上游能访问的 HTTPS 站点根地址（例如 `https://canvas.example.com`，不要附加 `/api`）；存储设置中的公网访问地址优先于该环境变量。

修改后需要重新创建后端容器，单纯重启旧容器不会更新环境变量。未配置时保持空值并由资源请求强校验，不会自动采用容器内网地址；这项设置不放宽出站 SSRF 校验，也不应为此开放数据库或后端端口。只做本地界面开发且不向模型提交资源时可以不设置。部署后仍需验证真实资源 URL 能被目标供应商读取，健康检查不能替代该验证。

## 一键启动（Windows PowerShell）

在仓库根目录执行：

```powershell
.\scripts\start-local.ps1
```

脚本会：

- 使用 `.local/project-workbench-debug` 作为后端 SQLite 开发数据目录；
- 调用统一后端管理入口，首次没有程序时构建 `.local/bin/canvas-backend.exe`；
- 首次启动时，如果 `web/node_modules` 不存在，执行 `bun install --frozen-lockfile`；
- 在后台启动服务，重复执行复用当前项目已启动的后端和 Vite；
- 将后端进程身份记录在 `.local/run/backend.json`，前后端日志写入 `.local/logs`；
- 将前端 `/api` 请求代理到 `http://127.0.0.1:8080`。

启动后访问 [http://localhost:3000](http://localhost:3000)。后端健康检查地址是 [http://127.0.0.1:8080/api/health](http://127.0.0.1:8080/api/health)。

脚本默认使用本地开发端口：前端 `3000`，后端 `8080`。不属于当前项目管理记录的进程占用端口时，脚本报错并保留对方进程；不会按端口或名称批量结束程序。`start-canvas.ps1` 继续复用该入口并打开画布。

### 后端启停与更新

```powershell
.\scripts\backend-local.ps1 status
.\scripts\backend-local.ps1 start
.\scripts\backend-local.ps1 stop
.\scripts\backend-local.ps1 restart
# 更新源码后构建并切换；构建失败时当前服务保持运行
.\scripts\backend-local.ps1 restart -Build
```

常规启停由同一个脚本完成，不需要到任务管理器找进程。进程固定叫 `canvas-backend.exe`；旧的按功能命名程序不是应继续使用的入口。单独的 `.local/start-backend.ps1`（若存在）也应转发到该管理脚本。

脚本使用 PID、启动时间和完整程序路径核对进程，序列化同时到达的管理操作；启动完成须通过就绪检查。更新时保留 `canvas-backend.previous.exe`，失败构建不会停止运行中的服务，程序更新不恢复或覆盖数据库。

正常退出通过本次启动专属的本地文件请求触发现有 HTTP 排空、Worker 关闭和数据库关闭流程。`CANVAS_LOCAL_STOP_FILE` 由管理脚本自动设置，默认没有此变量时仍使用原来的系统信号退出；不增加网络关闭接口。日志会记录 `backend stopped gracefully`。退出等待超时会保留进程记录并报告仍在排空，可再次查看状态或重试，默认不强杀。运行中的模型调用是否恢复仍由原有任务恢复与计费规则决定，不保证重启对模型响应无影响。

数据目录仍为 `.local/project-workbench-debug`。`-Port` 可用于独立检验目录中的测试实例；同一仓库只维护一份后端管理记录，不应启动多份进程操作同一开发数据库。

如果 PowerShell 的执行策略阻止脚本运行，可以只对当前进程临时放行：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\start-local.ps1
```

## 手工启动

后端：

```bash
mkdir -p .local/project-workbench-debug .local/cache/go-build .local/cache/go-mod
cd backend
CANVAS_BACKEND_ADDR=127.0.0.1:8080 \
CANVAS_BACKEND_DATA_DIR=../.local/project-workbench-debug \
GOCACHE=../.local/cache/go-build \
GOMODCACHE=../.local/cache/go-mod \
go run ./cmd/server
```

前端另开终端：

```bash
cd web
bun install --frozen-lockfile
bun run dev
```

`web/` 只使用 `bun.lock`。不要用 pnpm 或 npm 往同一套 `node_modules` 里再装一遍。

前端默认监听 `0.0.0.0:3000`，Vite 将 `/api` 和 OAuth 回调代理到 `127.0.0.1:8080`。如需修改代理目标，可设置 `VITE_API_PROXY_TARGET`。

开发和预览服务从 `web/.env.local` 的 `CANVAS_DEV_ALLOWED_HOSTS` 读取逗号分隔的受控域名列表（仅域名，不含协议和端口）。该变量仅供 Vite 配置读取，不进入浏览器构建。实际映射域名只放在 Git 忽略的本地文件；不要写进源码或关闭主机校验。修改开发环境文件后 Vite 会自动重启，预览服务需重新启动。

映射服务若把 Host 改成本地地址，浏览器 Origin 仍是外部地址，后端需要明确允许该来源。在 Git 忽略的 `.local/backend-config.json` 配置 `corsOrigins` 字符串数组，每项是完整来源（协议、域名和实际访问端口，不含路径），然后执行 `scripts/backend-local.ps1 restart`。未设置时保留本地默认值；进程环境变量 `CANVAS_CORS_ORIGINS` 优先于本地文件。这个来源策略覆盖登录、会话、写入及预检请求，无需给每个业务接口分别放行。域名映射继续使用同源 `/api`，不要修改浏览器 API 基址为本机回环地址。

反向代理应保留原始 Host 和端口、`X-Forwarded-Host` 与 `X-Forwarded-Proto`，Nginx 配置使用 `$http_host` 传递外部主机和端口；Cookie 由访问主机归属，HTTPS 由转发协议判断。不要使用任意来源通配配置来绕过检查。

### 局域网访问

同一局域网的设备可访问启动脚本显示的 `http://<本机局域网IPv4>:3000`，在该地址重新登录即可。前端通过同源 `/api` 代理访问后端；保留默认相对 API 地址，不将客户端请求指向 `localhost:8080`。后端继续监听回环地址，无需向局域网开放 `8080` 或放宽跨域策略。

Windows 防火墙启用时，仅允许同一局域网访问 TCP `3000`；不要关闭防火墙或开放数据库端口。局域网 IP 随网络变化时，重新运行 `scripts/start-local.ps1` 查看地址。

HTTP 局域网页面缺少安全上下文 API。客户端标识统一使用已有 `createClientId`，内容摘要优先使用 Web Crypto、缺失时通过 `@noble/hashes` 生成相同 SHA-256，保证重试、素材和同步幂等键不变。浏览器系统剪贴板、本地 Runtime 签名等要求安全上下文的功能仍需 HTTPS；不放宽签名或权限校验。

## 时间线字幕转写（whisper.cpp）

时间线“字幕转写”由**本地 whisper.cpp server** 执行：后端将片段音频预处理为 16k mono wav 后，POST 到 `CANVAS_WHISPER_BASE_URL/inference`（whisper server 原生接口，`response_format=verbose_json`）。未配置该地址时，转写任务会立即明确失败，提示“撰写失败未配置本地转写服务”。

### 安装 whisper-server

```bash
brew install whisper-cpp
```

### 下载模型

仓库脚本将模型放在 `.local/whisper-models/`（已被 `.gitignore` 忽略）。多语言模型（含中文）用 `ggml-base.bin`（约 141MB）；网络受限时可用 aifasthub 镜像：

```bash
mkdir -p .local/whisper-models
curl -fL -o .local/whisper-models/ggml-base.bin \
  https://aifasthub.com/ggerganov/whisper.cpp/resolve/main/ggml-base.bin
```

### 启动服务

```bash
scripts/start-whisper-local.sh
```

脚本默认以 `ggml-base.bin` 监听 `127.0.0.1:8082`（`-l auto` 自动识别语言）。需要换模型或端口时：`WHISPER_MODEL=ggml-small.bin WHISPER_PORT=8083 scripts/start-whisper-local.sh`。

### 让后端指向该服务

后端不读取 `.env` 文件，环境变量必须由启动 shell 注入（在手工启动命令基础上追加）：

```bash
cd backend
CANVAS_BACKEND_DATA_DIR=../.local/project-workbench-debug \
CANVAS_WHISPER_BASE_URL=http://127.0.0.1:8082 \
go run ./cmd/server
```

### 验证

```bash
# 服务就绪：返回 200/404 即可
curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8082/
# 冒烟：20 秒语音 → verbose_json 字幕段
curl -s -X POST http://127.0.0.1:8082/inference \
  -F 'file=@sample.wav' -F 'response_format=verbose_json'
```

## Docker 开发

需要容器化热更新时，在仓库根目录执行：

```bash
LOCAL_UID=$(id -u) LOCAL_GID=$(id -g) \
  docker compose -f docker-compose.dev.yml up --build
```

Docker 开发编排也使用 `.local/project-workbench-debug`，并默认暴露前端 `3000` 和后端 `8080`。端口冲突时，可通过 `CANVAS_WEB_HOST_PORT` 和 `CANVAS_BACKEND_HOST_PORT` 调整宿主机端口。
