# 文本协议影响评估

## 结论

可以让已经确认支持 Responses 的文本模型优先使用 Responses，不能仅凭“文本模型”或“OpenAI 兼容”批量强制切换。支持情况必须以同一渠道、同一模型为单位确认；普通文本成功不代表工具调用、图像输入或 JSON Schema 也支持。

自动模式现在同时覆盖普通生成和 Agent；固定模式保留指定默认协议。已有模型没有支持声明时保持原行为。本批没有修改真实模型配置、计价或数据库结构，也没有调用收费模型。实现前只读检查本地目录：11 个启用文本模型均使用 Chat Completions，没有协议支持声明；因此不能把本批模拟测试当作这 11 个模型均可迁移的证据。

## 影响范围

| 入口 | 共用链路及本批处理 | 业务影响与待验收 |
| --- | --- | --- |
| 文本节点、AI 改写、项目生成 | `generation-task.ts -> CreateTask -> runTextTask`；普通文本自动优先已声明 Responses | 节点和历史格式不变；真实正文质量待验收 |
| 选题、制作方案、集纲、正文、分镜 | 现有后台文本任务；声明式请求补齐思考、输出上限和结构化输出，参考图转为 Responses 内容块 | 下游需要结构化结果时不再静默漏传参数；真实模型对严格 Schema 的支持待验收 |
| 多集和长文分批 | `workflow_text_batch.go` 子任务仍通过 `CreateTask` | 本地编排及已完成批次保留；新子任务使用当前声明，不把 Responses 当作无限上下文 |
| 制作资产 Agent、画布 Agent、Pi 步进 | `agentRequests.canonical -> runAgentToolTask` | 保持工具结果关联、可选参数语义、产物提交和权限校验；真实多轮工具调用待验收 |
| Agent 记忆压缩及后台派发 | `cloud_agent_memory_compact.go`、`cloud_agent_pi_model.go`、`cloud_agent_runtime_scheduler.go` 进入同一任务准入 | 普通压缩与 Agent 步骤均覆盖；没有引入第二套会话存储 |
| 时间轴 AI 编辑、提示词优化、审美检查、前台模型测试 | `requestImageQuestion/requestToolResponse` 同步中转；新增共用协议选择，修复 JSON/SSE 返回与未完成判定 | 同步入口仍是同步调用，不因本批修改自动拥有后台任务续跑；扩展协议需后台适配器执行 |
| 管理后台模型测试 | `TestAdminChannelModel` 采用普通生成的协议选择规则和鉴权格式 | 测试端点与普通生成保持一致；仍需单独验收 Agent 能力 |
| 系统渠道同步中转 | 端点按数据库支持声明授权，不信任浏览器支持列表，不改写已有协议请求体 | 未授权端点拒绝；固定模式不会被客户端绕过 |
| 重试、恢复、备用渠道 | 当前尝试固定协议；逻辑模型重新选路时移除旧渠道选择并按新渠道配置固定 | 禁止未知结果时换端点重发；新 Agent 步骤和分批子任务独立准入 |
| 流式、用量、费用 | 共享终态校验，保留用量；前端 JSON 回退、失败取消读取；同步未完成结果进入费用核对 | 中断或 token 耗尽不能变成成功正文；真实供应商用量和费用需人工核对 |
| 图片、视频、语音、独立工作流 | 各自原有媒体适配器和执行器 | 不跟随文本切到 Responses；模型的模态能力不会因协议变更自动增加 |

## 兼容边界

- Responses 请求的 `input`、内容块、工具定义、工具结果和 `text.format` 均与 Chat Completions 不同；只改 URL 不可行。
- 默认不启用供应商响应存储；本地 Agent 和任务仍负责历史及断点恢复。没有采用供应商后台模式、服务器会话或加密推理状态续传；选择 Responses 本身不会补全这些功能。
- 原始 HTTP 响应使用 `output[].content[]`，不能依赖 SDK 的 `output_text` 便利字段。最终完整结果优先于临时增量文本。
- SSE 缺少完成结果、`response.failed`、`response.incomplete`、拒绝或空输出明确失败，不覆盖为完整正文。旧中转不规范地只返回增量而没有完成事件时，将显示错误，需要渠道修复。
- 工具未设置 `strict` 时显式设为 `false`，保留已有可选参数；原本显式严格的工具保持严格。结构化正文的严格 Schema 参数保持业务设置。
- 版本号是 URL 组成规则，不是兼容探测。前后端保留代理路径、显式版本、转义和查询参数，不尝试轮流调用 v1/v2。
- 文本协议适配不保证任意模型支持图片、视频、音频参考；本批 Responses 文本路径对尚未实现的音频参考明确拒绝，不能静默丢弃。原生模型的多模态输入仍须专项验证。
- 模型名、正文保存、连线和阶段信息不迁移；输出风格、推理 token、延迟和费用可能变化，不能承诺仅改协议就更快或更省。

## 验收与回退

先选择一个已知支持 Responses 的测试渠道模型，启用自动策略并声明支持；分别验证短文本、参考图、结构化正文、工具调用和多轮工具结果。再验证长分批、后台关闭后恢复、取消、上游限流、断流与失败重试。真实计费请求由用户手动触发。

重点确认历史节点可以继续编辑、生成结果正确关联、失败不覆盖旧正文、同一任务不重复计费；检查 token 和缓存用量。普通连接测试不能代替这些验收。

可以用固定策略恢复原默认协议；已进入队列的尝试仍保留入队时选择。程序回退先排空本版本任务，并继续使用现有数据库；不要用旧备份覆盖验收期间的新数据。本批没有数据库迁移。
