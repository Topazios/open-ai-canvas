# 分镜场次并发

分镜采用 `storyboard-scene-v4`。主 Agent 负责读完整正文、整理制作约束、规划场次和镜头清单，最后审查整集；服务端按镜头工作量和显式依赖分配子 Agent 模型任务，不再把场次作为并发边界。子任务通过现有任务队列调用模型，不为每个镜头常驻一个独立进程。

## 执行过程

1. 主任务确定场次编号、正文覆盖范围、入口和出口、时长，以及稳定的镜头编号、数量和空间基准。尚未完成这些规划时不派发场次任务。
2. 主 Agent 可在镜头规划中把相邻简单镜头合为一个 `taskGroup`，复杂镜头独立成组；不填时服务端将普通短镜头最多两镜合组，长镜头或跨度较大的镜头独立分派，每组最多四镜。不同工作组（包括同一场次内）可以并发。
3. 只有确实需要前镜内容才能保证动作、道具或状态连续时才写 `dependsOn`。在自适应分组模式中，同场相邻镜头若已有明确的前镜出口、当前镜头入口及双方摄影规划，可按这些固定约束并发起草，不必逐镜等待生成结果。跨场、非相邻或约束不完整的依赖仍等待已保存结果。子任务读取完整场次正文、当前分配镜头、必要的前置镜头或规划和已有资产编码，只允许提交领取范围内的镜头；跨组写入、跳镜和旧版本结果不会落盘。并发起草不替代最终连续性审查。
4. 每批合格镜头、任务表和进度事件在同一数据库事务中保存。下一批从已保存位置领取；输出超限时批量由 4 镜降为 2 镜、1 镜。单镜仍超限时保留进度并等待调整。
5. 局部审查问题用镜头编码返修，只撤下该镜及其明确依赖的下游镜头；无关镜头、布局和已有素材继续保留。需要改范围、数量或时长预算时才重规划整场。所有组补全后主任务核对整集覆盖、对白、动作、时长和连续性；工作组返回不等于整集已经通过审查。

并发沿用全局 Agent 任务限额和现有模型队列；不会绕过渠道限流、计费或审批。实际耗时取决于场次依赖、并发配置和上游响应，不承诺固定倍数提速。

## 任务身份和保存边界

任务以运行 ID 和稳定工作组编码定位。每次领取另外保存所属场次、执行代次、模型任务 ID、镜头范围、批次偏移和输入指纹。提交时同时校验当前拥有者、执行代次、场次规划及本组真正引用的前置结果；按固定规划并发的相邻镜头校验规划指纹，其他依赖校验实际结果指纹，避免前组正常完成使后组在途结果失效。场次完成状态由服务端根据镜头保存情况推导，不依赖模型填写的布尔值。

主任务也有独立执行代次和租约。旧主任务的工具调用、模型结果、会话快照和最终完成通知不能覆盖新主任务。子任务结果依据场次任务表验收，不因主任务换代而全部作废。

结果和可重放事件共同提交到现有运行状态、分镜产物和 `cloud_agent_event_records` 事件表，无额外消息队列。实时通知丢失后，客户端按事件序号重放并重新读取服务端进度；相同事件合并去重。

## 重派与恢复

“重派工作组”先在事务中撤销旧领取关系、增加执行代次，再取消旧模型任务，保留已保存镜头并为缺项重新领取。旧调用即使迟到，也不能写回。历史执行和计费记录保留，旧分配从当前调度中移除。

主任务失败、暂停、取消，或被检查器判定租约过期、卡住时，整集停止。服务端先在同一事务中撤销主、子任务的执行权限并保存暂停状态，再取消排队和在途请求；迟到结果不能写回。已保存镜头保留，后台扫描不会自动重新启动整集。

节点详情和容器内各集任务提供“重试主任务”，通过 `retry_main` 从任务表和已保存镜头继续，重新分配停止后未完成的工作组。仍在运行时也可手动重新激活主协调器，此时保留健康子任务；已完成整集不提供重试。失败分配全部重置后才启动主任务，避免重置一半便开始执行。正文、来源关联或参数被修改时拒绝覆盖并显示原因；仅画布退回可由已保存镜头精确还原的旧进度时，手动重试会修复显示。

子任务的临时上游错误沿用现有退避重试。重复内容错误按现有规则停止，单个场次批次即使错误内容持续变化，也最多进行 6 次校验失败尝试。已有进度推进后再计下一批，避免成功内容被重复生成。

重试上下文的下一镜号、偏移和工具参数均来自当前领取表。工具限制当前场次、镜号、批量上限及规划中的段号和时长；旧稿只保留当前领取范围且段号、时长仍匹配的部分。时长不符时明确反馈期望值与实际值，不能用旧审查预算覆盖新规划。

模型误提交整场时，仅可提取当前任务拥有的镜头，已知同场其他组镜头不写入；未知、重复、跨场镜头仍拒绝。误带的 `goal/entry/exit/dependsOn/taskGroup` 仅在与权威规划完全一致时移除，不改变内容、镜号、段号或时长。归整结果仍通过原有完整性与归属校验，成功时记录处理事件，原始模型响应保留以供审核。真正的内容错误继续自动反馈修复，不用降低验收标准或无限重试掩盖失败。

同一校验问题连续耗尽修复额度时，等待其他在途工作结束后停止整集，明确记录镜头工作组及原因，等待手动重试。重试清空旧工作组的失败计数和暂停状态，不删除已保存镜头。摄影细分字段完整但遗漏 `camera` 时，仅将本次已提交的景别、机位角度、运动和走位原样整理为汇总；缺少必要信息仍返回具体字段错误，不用默认值冒充完整分镜。

## 回收机制

| 项目 | 当前规则 |
| --- | --- |
| 主任务续租 | 每 20 秒更新，租约有效期 90 秒 |
| 主任务空转 | 无活动模型任务、非暂停且 2 分钟没有进展时停止整集，等待手动重试 |
| 过期任务扫描 | 启动时执行，此后每轮结束等待 60 秒再扫描 |
| 模型执行期限 | 读取 Agent 步骤配置的超时，另留 30 秒收尾时间 |
| 排队任务 | 不将排队等待时间当作执行超时 |
| 取消宽限 | 单次内部取消最多等待 30 秒；失败记录留待后续清理 |
| 终态运行 | 失败或取消后仍扫描尚未完成的撤销清理记录 |

仅取消本运行拥有的任务和会话，不按进程名称批量终止。无法保证供应商已受理请求立即停止或不再计费；本地旧拥有者失效与结果隔离先完成，供应商状态和费用继续走现有对账流程。

## 使用与验收

容器任务详情显示镜头工作组、所属场次、已保存镜头数、执行代次及状态。展开工作组可查看领取任务、问题原因和历史记录；整集停止后不能通过单项重派偷偷恢复整集，必须先重试主任务。主任务继续不会把全部场次重新生成。

旧整集串行任务仅在没有在途调用和并行工作记录的安全检查点切换，保留已有分镜和媒体。已结束任务不会被自动重做。

验收需核对：独立场次同时执行、依赖正确等待、单场重派后旧结果被拒绝、主任务重启后健康子任务继续、通知断线后进度恢复、最后整集审查通过。真实供应商端到端生成和性能测量属于独立验收项，单元测试与服务就绪不能替代。
