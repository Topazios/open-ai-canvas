状态：核心流程与连续性改造已实现，真实媒体质量和完整交付仍待验收。修订日期：2026-10-23。

## 当前执行口径

以下顺序覆盖本文历史批次中不同的阶段拆分与人工确认要求：全局设定与选题 → 合并制作方案与规范 → 资产总表、造型转换表、声音总表 → 独立资产按依赖并发制作 → 分集集纲与正文 → 正文原位诊断与修复 → 按集分镜列表 → 首尾帧、关键帧、视频、配音与音效引用 → 剪辑混音与交付检查。无必须由用户点击的待确认状态，用户可以自行检查编辑后执行下一步。

本批已实现独立实体和变体编码、状态变化的来源依据、统一八格资产图及系统中文标签、物理尺寸与镜头投影分离、相关集上下文筛选、声音类别和统一人物试听文本，以及原资产的资料与试听入口。编号由服务端现有持久序列分配；造型改名保留编号。帧图不引用音频指令，视频按关联 AUD 引用声音，实际模型能力仍由现有准入规则校验。

人物试听接入已有语音协议和全局音频并发，不等同于声音克隆；道具、环境和音乐的实际音频使用已有导入引用，尚未新增专用生成协议。剪辑、混音与交付复用现有能力，本批没有自动生成一部作品并验收导出。未调用付费模型，已有文稿与媒体不自动重做。

自动检查：前端 149 项测试、1647 条断言及生产构建通过；后端制作任务、handler 和 generation 包测试通过；隔离 API 的真实页面完成 14 项浏览器检查，覆盖明暗主题和窄屏，并验证八格合成像素。完整真实媒体与连续性验收清单见 `pending-test.mdx`，不能以历史进度估算代替验收。

## 1. 目标与范围

将当前画布五步导引与项目六阶段工作台整合为八个业务阶段：

项目与剧本 → 美术与资产 → 导演与分镜 → 配音与声音 → 镜头视频 → 剪辑与后期 → 成片质检 → 导出交付。

保留 React、LeaferJS、现有视觉规范、项目资产、任务队列、模型路由和时间线编辑器。项目负责持久化制作对象；画布负责内容展示、关联与自由布局；工作台负责列表、编辑、审核和批量操作。两个入口操作相同业务对象。

实施顺序以现有功能为准：直接复用 → 补入口与数据衔接 → 调整现有行为 → 证据确认缺失后最小新增。八阶段是现有能力的业务编排，不默认新建八套页面、编辑器、业务状态仓库或通用工作流引擎。本版以第 2 节复用矩阵和第 7 节 I0–I5 整合批次为执行基准；第 4 节是目标验收范围，不是同名组件/服务新建清单。

本方案是短剧业务流程建设，独立于此前无限画布性能重构。实施时保留工作区现有修改，按批建立可恢复检查点。任何必要的数据结构变更单独交付，不伪装为画布性能修复。

范围包括全部子流程。高级特效、专业级调色、自研配音/口型模型、平台自动发布不作为第一条端到端链路的前置条件：先支持导入外部加工结果，再按独立验收标准接入受支持的自动能力。暂不支持的控制必须明确显示不可用，不能做成空操作按钮。

## 3. 工作界面与操作合同

### 3.1 两个入口、一份业务内容

顶部显示八阶段与当前集数；点击阶段后打开子任务列表，并定位对应工作台或画布对象。优先复用现有侧栏和面板，不同时叠加多个遮挡画布的大面板。章节编辑、资产管理、分镜制作、剪辑成片继续使用现有页面/路由；阶段切换携带 project/unit/shot 上下文及返回位置，不要求每个阶段再造工作台。

子任务显示名称、作用范围、必要/可选、阻塞原因、任务执行状态、审核状态和数量。工作区根据内容呈现文本编辑器、资产浏览、分镜表、音频试听、视频对比或时间线。参数/引用/版本沿用已有面板。

画布节点绑定业务 ID 及采用版本，不复制一份可独立编辑的镜头主记录。节点位置、选中状态、视口仍归画布；镜头正文、产物、审核归项目业务入口。手工与 Agent 使用相同写入合同，不能绕过审核或后台幂等校验。

同一镜头允许在多个画布显示，但业务内容一致；删除显示节点与删除业务镜头必须明确区分。未关联项目的自由画布继续原有工作方式，也可使用原有生成/剪辑功能，不强制搬迁。仅当使用项目级集数管理、审核和交付归档时，复用现有创建/关联项目入口并提供映射预览，用户确认后建立关联，旧节点不静默改写。

### 3.2 每个子任务的最小合同

| 内容 | 规则 |
| --- | --- |
| 身份 | 稳定任务标识、模板版本、阶段/子任务键、project/unit/scene/shot/dialogue 作用范围 |
| 输入 | 明确引用对象 ID、版本、必要字段；记录本次生成所用快照 |
| 操作 | 编辑、保存、导入、生成、取消/重试、比较候选、采用、提交审核、确认/退回 |
| 产物 | 复用资源与产物版本；明确当前编辑稿、选中候选、已确认版本 |
| 审核 | 确认对象版本、确认人、时间、问题单；内容修改后旧确认不自动继承 |
| 并发 | 写入带预期版本，冲突不覆盖；生成提交有幂等键，重复回调不重复登记 |
| 恢复 | 刷新后恢复任务/草稿/选用状态；本地保存与服务端保存分别提示 |

“采用候选”与“审核通过”是两个动作。允许提供“采用并确认”快捷操作，但服务端必须分别满足条件、记录具体版本。

### 3.3 状态和完成规则

- 执行状态复用任务中心：未开始、排队、运行、成功、失败、取消。取消仅在供应商/Worker 支持时表示实际取消；不能取消时如实显示，不谎报。
- 审核状态独立：草稿、待审核、已确认、需修改、需复核。I0 核对现有状态表达，I3 按实际缺口决定是否扩展工作流存储枚举，不能直接将前端文案当成既有 API 枚举。
- 可选任务单独记录不适用/已跳过及原因；必需任务不能用跳过达成最终交付。
- 必需子任务具有有效产物、必要审核通过、阻断问题为零，才完成阶段。分母为当前适用对象，空列表不得自动通过；无对白等场景通过显式“不适用”处理。
- 展示已生成、已确认、需修改数量，不将生成成功数量作为总完成率。跳过与通过在界面上分别显示。
- 阶段顺序用于导航；执行按依赖图判断。项目资产可共享，第 1 集制片、第 2 集写作可并行，不要求整部剧同时前进。

| assets.environments | 场景空间、机位、昼夜与道具形态版本 | 必要场景/道具版本就绪 |
| assets.approve | 资产版本审核、适用场次及镜头引用 | 必要资产已确认，无失效引用 |

不要求所有角色都生成多视图、所有场景都生成昼夜版；由当前镜头需求定义必需项。重复提取不得重复创建同一已确认资产；自动归并只出建议，确认后执行。

### 4.3 导演与分镜

| 子任务键（拟定） | 实现与产物 | 通过条件 |
| --- | --- | --- |
| direction.scenes | 场次表演目标、走位、空间/视线/轴线和节奏编辑 | 需要的导演说明确认 |

| direction.boards | 复用分镜图生成与导入，逐镜候选对比和确认 | 适用镜头已有确认参考或替代方案 |

旧 storyboard/previz 分别映射到此阶段的文字/图片分镜和预演子任务。沿用其数据，不复制产物。当前 previz 界面使用图像能力生成 action_board，不能直接称为已有动态视频预演；动态预演需另接时间线或视频任务。

| 子任务键（拟定） | 实现与产物 | 通过条件 |

| voice.dialogue | 从定稿抽取台词、旁白、说话人、情绪、停顿和读音；逐条纠错 | 台词稳定 ID，引用场次/镜头明确 |
| voice.casting | 复用角色声线配置，试听/导入声音并记录用途 | 所需角色声线确认 |
| voice.recording | 逐句生成或导入，试听、比较、选择，原音保留 | 适用台词有确认音频 |

一条台词可跨镜头，一个镜头可含多句。关联必须表达音频和镜头内的时间区间，不能只给镜头挂一个 audio ID。无对白镜头可独立开始视频制作；正式口型只使用确认音频，临时音频保留临时标记。

| video.generate | 复用任务中心和制作工作台；按镜头提交、导入、重试 | 结果资源有效，不自动审核通过 |

全部修改走既有编辑命令/撤销/保存；不新建独立 store 复制 TimelineProject。自动组装只首次创建，重复进入不能覆盖手工剪辑。更新镜头采用版本时展示替换差异，保留剪辑点；新素材过短时明确要求修正，不静默拉伸。

### 4.7 成片质检

| 子任务键（拟定） | 实现与产物 | 通过条件 |
| --- | --- | --- |
| review.automatic | 核对缺失资源、过期版本、空镜头、时长、字幕边界；媒体检测逐项接入 | 可确定的问题有定位；未覆盖检查明确待人工 |
| review.screening | 渲染可播放的审片版本；时间点批注、级别、镜头/素材定位 | 人工审片完成，阻断问题清零 |
| review.revision | 跳转来源修改、重新渲染、对比和复审 | 确认对应时间线修订及实际审片文件 |

AI辅助检查不直接关闭人工问题，黑帧/静音检测需要人工判断是否为创作意图。问题定位优先稳定对象 ID 加片段内偏移，时间线修改后重新映射；映射失败明确提示，不能批注到错误画面。

此阶段可以创建审片渲染任务，避免“必须先交付才能审片”的循环依赖。最终导出只认可已审版本；改变剪辑、混音、字幕或影响内容的导出设置后，需要按影响重新审核。

## 5. 数据与服务端实施

### 5.1 持久化策略

优先复用 Project/Unit、资产及版本、Shot/ShotRevision、ShotArtifact、ShotAssetReference、WorkflowInstance/Step、任务与资源。新增能力按以下责任补齐，逻辑对象不等于立即新增同名表：

| 待补合同 | 必须保存的内容 | 落地原则 |
| --- | --- | --- |
| 剧本/场次版本 | 原文来源、制作正文、集/场映射、确认版本 | 先审计现有 unit/revision 能力，缺失才增量扩展 |
| 子任务定义/实例 | 稳定键、父阶段、scope、输入要求、可选条件、依赖、进度 | 基于现有工作流模板版本与实例扩展 |
| 台词与音频关联 | 说话人、正文版本、音频采用版本、时间区间 | 复用声音资产和产物；独立表达台词身份 |
| 版本依赖 | 下游产物引用的对象版本、字段域、输入指纹 | 可查询、可精确失效，不依靠画布连线猜测 |
| 审核与问题 | 审核对象/版本、状态、确认人、时间点、问题处理记录 | 追加历史，不能覆盖掉原确认依据 |
| 时间线与交付 | 集数关联、时间线版本、审片资源、导出输入和清单 | 沿用现有快照/保存入口，补按集关联和来源绑定；服务端归档按验证后的缺口单独扩展 |

结构化 JSON 只放可校验的配置与输入快照，不将审核、并发和关联关系塞进无 schema 的 metadata。I0 先记录已有 schema/API 能力，I1–I4 按实际缺口逐项提出最小差异，不要求先完成所有新对象才接通旧功能。没有数据缺口就不迁移；确需增量迁移时同步数据库/API文档及 SQLite/PostgreSQL 测试。

### 5.2 服务端动作合同（拟定，不代表接口已存在）

- 获取模板/实例/子任务进度：返回阻塞原因、对象数量、可选规则与允许动作；服务端计算权威状态。
- 保存子任务输入：校验所属项目、对象范围、预期版本；事务提交并标记受影响依赖。
- 提交生成：复用任务 API，带幂等键、目标对象、输入版本和输出角色，不另建任务队列。
- 登记或导入产物：校验成功任务、资源所有权、版本和 media type；一个任务输出重复登记只返回已有结果。
- 选择候选/提交审核/审核确认：带目标产物版本及 expectedRevision；并发冲突返回现有错误合同，不最后写入者静默覆盖。
- 跳过/重新打开：服务端检查是否可选、理由与下游影响，不依赖前端按钮隐藏保障规则。
- 修改影响预览：返回受影响镜头、音频、剪辑片段、审核和交付；确认更新后只重算相关对象。
- 导出/打包：复用任务基础设施，固定源快照和配置；授权下载沿用资源访问服务。

每个写动作的事务至少包含业务变更、版本推进、必要进度更新及依赖失效。若涉及异步通知，沿用既有可靠任务/事件机制，不能在响应返回后靠浏览器继续完成关键落盘。

### 5.3 旧流程进入新流程

先为现有五步/六步建立统一展示映射，不为了增加导航标签立即创建新模板版本。如果新增阶段确认和持久化规则确实超出现有模板，再按既有模板机制升级（拟 v3），且现有 v2 实例不自动被当作八阶段已完成。届时提供显式升级预览及可重试的映射过程；旧阶段状态和原始数据保留可追溯记录，不长期维护两套独立业务写入入口。展示映射阶段的新审核/交付项缺少证据时保持待确认，不推导成完成。

| 旧数据 | 新流程映射 |
| --- | --- |
| 画风、故事、story/assets | 导入项目设置/剧本/资产子任务；已有内容可复用，未记录审核的不补造确认 |
| storyboard/previz | 归入导演与分镜；镜头和产物 ID 保留 |
| video | 保留已有视频与选择状态，审核状态按证据确定 |
| final/delivery | 保留旧成片，可作为待审候选；不能直接推定符合新交付合同 |
| 新增配音/后期/审核任务 | 按输入数据判为待处理或待确认的不适用，不一律强制重做 |

升级失败不丢失旧内容，重复执行不得创建重复资产/镜头/实例。业务回退以停用新入口、保留新增数据为主；不得恢复旧数据库覆盖用户新作品。旧客户端可能丢弃未知字段时，必须在实际数据扩展前加版本门槛或安全降级，不能无条件宣称旧版可读写新格式。

## 6. 变更影响示例

| 修改 | 自动标记 | 不应发生 |
| --- | --- | --- |
| 第3镜台词变化 | 相关配音/口型/字幕需复核，必要时镜头时长需调整 | 全剧重新生成或自动扣费 |
| 角色正式服装变化 | 引用该版本的分镜/视频需复核 | 替换所有历史资源文件 |
| 镜头位置/画布视口变化 | 只更新画布布局 | 使内容审核失效或发起生成 |
| 镜头顺序变化 | 相邻连续性、时间线及审片版本需复核 | 将未确认新排序覆盖手工剪辑 |
| 采用新视频候选 | 提示更新引用它的剪辑片段和审片 | 覆盖时间线入出点或旧候选 |
| 删除镜头 | 更新适用数量，引用片段明确提示缺失，迟到结果只可按策略归档 | 自动复活镜头或继续加入正式成片 |

先验证现有功能，再连接现有入口/数据，最后补必要缺口；以下 I0–I5 是整合批次，不等同于用户看到的八阶段。

| 批次 | 工作及主要模块 | 本批必须交付 | 退出条件 |

| I3 保存、版本与确认补齐 | 在现有保存/状态合同上补必要关联；解决按集时间线归属，审核/采用区分及修改影响；已补保存适配器依赖、失败重试和脚本影响提示 | 刷新恢复、集数隔离、真实保存提示、必要确认记录；缺失云端归档按增量设计补齐 | 代码子任务已完成并通过专项检查；版本冲突/迟到结果/断网及人工操作仍待验收 |
| I4 审片与交付衔接 | 复用现有预览、就绪统计、转写/字幕及导出；已补项目/集交付快照、问题记录、审片核验和交付清单展示 | 三镜头从剧本到现有 MP4 导出完整验收；资料 ZIP 作为独立后续任务 | 代码链路与构建已通过；仍需验证不漏镜、完整播放、导出与确认版本一致、刷新后可恢复下载 |

I0 后根据实际缺口拆成可独立审查的小变更并估算工期。不再把已有提取、生成、配音、剪辑和导出列为重建工期；此前画布重构的 12–20 个工程日也不作为本方案预算承诺。资料包、高级自动质检等增强单列，不能阻塞已有 MP4 链路整合，但整体目标未完成时必须明确保留待办。

### 7.1 整合优先的实现限制

- 不先建通用依赖引擎、全局审核平台或全新剧本编辑器；完成判断按当前短剧场景加入现有领域函数，多个实际调用需要时再提炼共享 helper。
- 不重复添加资产提取器、TTS 调用器、视频任务队列、时间线 store、字幕工具或导出器。重复入口可以保留，但必须调用既有业务方法。
- 已有功能不因整合强制重跑生成或重建产物；声音/视频模型不可用时支持原有素材导入，并明确能力限制。
- 新旧进度映射是展示和业务条件的整合，不能用前端勾选绕过后端完成校验。新增审核尚未落盘的阶段不能宣称已持久化确认。
- 若按集时间线需要新增存储键，保留原 `editor-timeline:<projectId>`，展示归属选择/迁移预览；不把同一项目时间线自动复制成每一集已完成工程。服务端归档需求与本地编辑保存分别设计和验收。

## 8. 验证方案

### 8.1 固定夹具

- 项目 A：已有成稿、单集三镜头、两角色、一场景、一道具；包含对白、旁白和无对白镜头，使用可解码的本地媒体。
- 项目 B：两集、共享角色资产；同名不同角色、别名、服装变体、跨镜头台词和背景音乐，验证作用范围与依赖。
- 项目 C：旧五步画布/六步工作流数据、历史候选、已有最终视频、未确认资产，验证升级和恢复。
- 故障场景：保存失败、存储失败、任务超时、重复回调、删除目标、两标签编辑、跨账号/项目资源引用、外部依赖未配置。

### 8.2 自动验收

| 范围 | 必测行为 |
| --- | --- |
| 工作流 | 按依赖并行、可选/必需、空集不能误完成、退回/重开、阶段汇总 |
| 版本 | 审核绑定版本、上游修改精确失效、候选采用和审核分离、旧结果可追溯 |
| 并发 | CAS冲突、重复提交/回填幂等、删除不复活、在途编辑不丢失 |
| 持久化 | 连续保存、断网刷新、恢复重试、账号隔离、退出/切换后的旧回调失效 |
| 升级 | 映射可重试、失败不破坏旧内容、不补造审核、旧客户端保护 |
| 剪辑 | 自动组装不覆盖手工剪辑、替换素材保留裁剪、时间线命令/撤销/保存 |
| 视听 | 本地音视频实际解码、时间区间合法、字幕与音画同步、已用效果的预览/导出对照 |
| 交付 | 任务终态正确、产物可读取/解码、规格验证、打包完整性、权限和敏感信息排除 |

前端按改动范围执行类型检查、构建及行为测试；后端执行受影响包的单元/集成测试，数据变更覆盖 SQLite 与 PostgreSQL。真实页面检查覆盖明暗主题、窗口边界、中文输入、内部滚动和流程/画布快捷键隔离。

新增流程对既有 500/2000 节点性能目标不得静默降低；开启与关闭流程面板分别记录影响。当前画布尚未完成的性能验收继续独立跟踪，不由新流程验收覆盖。

### 8.3 用户配合的人工验收

每批提供约 15–30 分钟清单：先选本批测试副本，按“编辑 → 保存 → 生成/导入 → 选用 → 审核 → 修改回退 → 刷新恢复”验证。真实模型调用及费用由用户手工触发；自动化使用模拟任务与本地媒体。

最终至少完成：一集从剧本到成片；修改一处台词只更新相关内容；替换一处资产复核相关镜头；断网编辑后恢复；双标签冲突保留草稿；导出后完整播放核验。问题记录步骤、期望、实际、截图/录像及对应版本。

## 9. 交付与回退纪律

- 每批提供源码差异、固定测试版本、自动检查结果、人工清单、已知边界和回退命令/步骤；只在实际通过后更新待测试记录，不把计划任务标为已实现。
- 前端 UI/状态/接口、后端规则/持久化/异步任务共同验收；不能只交付菜单或成功提示。
- 测试只使用副本；真实资产不删除、不自动重新生成。数据丢失、误删除、重复计费、无法保存、导出结果与确认版本不一致均阻断下一批验收。
- 新结构使用版本化和增量策略；先停入口再回滚有问题代码，保留已产生业务数据。若无法安全回滚，则采用前向修复，禁止恢复旧库覆盖验收期间的新作品。
- 文档同步到 `pending-test.mdx`、`todo.mdx`、功能页、代码地图；API/schema变化同步后端专题文档。方案状态随实际实施更新。

## 10. 推荐执行起点

先执行 I0 和 I1：以当前版本为基线实际验证已有能力，再统一阶段导航和上下文。在 I2 中打通“现有章节 → 现有资产/分镜 → 现有配音/视频 → 现有剪辑器”，I3 补实际保存与确认缺口，I4 接回现有渲染/下载并记录交付。全程以用户已有内容和已选产物为输入，不让流程整合变成整套系统重建。
