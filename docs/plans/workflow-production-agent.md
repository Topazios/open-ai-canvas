# 制作流程长任务 Agent 改造方案

状态：2026-10-14 已接入资产五分类的后台制作 Agent，正在验收。复用 Pi 运行时、任务计费、原生文本节点和容器；真实模型语义质量、成本与长时运行仍待人工验收。

本批已实现 A 的领域工具与画布入口、B 的同版本事实共享和人工编辑保护、C 的暂停继续及回执恢复保护。单集变化后会拒绝混合版本，新作业复用未变化正文事实；尚未提供原作业内选择版本、自动局部重写或冲突解决界面。D 的分集正文和分镜推广未开始，不能视为全部计划完成。

新增 schema 45，升级前必须保存一致性数据库副本和对应程序。旧 schema 44 程序不能直接读取升级后的数据库；代码回退需保留 v45 兼容性，不能用旧备份覆盖验收期间的新数据。

## 1. 目标与首批范围

将多集、多节点的提取、分解、归并升级为可规划、使用工具、校验、修订和恢复的后台 Agent 作业。首批覆盖资产提取与跨节点汇总，后续推广到分集正文和分镜。单节点简单改写继续使用现有文本生成入口。

保留现有 React 画布、阶段和步骤枚举、文本节点、资产容器、因果连线、模型选择和生成任务计费链路。人物、场景、道具、特殊资产与统一制作规范继续独立展示，共享按版本建立的正文事实。

核心验收目标是：用户启动一次任务后，可以离开页面；回来时知道哪些材料已处理、哪些资产已产出、哪些存在冲突，以及怎样从中断处继续。完成状态必须有产物和覆盖检查支撑。

## 3. 一次资产任务的工作过程

1. 接收正文容器、目标类别、模型及运行预算，读取实际成员清单与版本，建立来源清单。
2. 检查已存在的同版本事实与资产，建立“待读取、待提取、待归并、待检查”的计划。
3. 按集和场次分页读取原文。按实际模型预算拆分长单元，并保留来源段落和未读游标。
4. 增量提交人物、空间、道具、特殊元素、规则、风格与声音事实。每条事实记录来源节点、版本、集号及可定位证据。
5. 归并别名和重复主体；状态变化保留为变体，冲突保留为待确认项。事实与创作建议明确区分。
6. 按用户请求的类别读取事实子集，逐资产生成和保存内容。只请求人物时，不自动执行全部分类生成。
7. 检查来源覆盖、结构完整性、引用有效性、重复资产和跨集冲突。缺失类别或结果异常时有针对性地重读和修复。
8. 提交分类产物和覆盖报告。用户可以随时查看已完成资产；尚未产出的分类显示真实状态。

一个主 Agent 负责计划与决策。确定性的分页、索引、版本比较、提交和规则校验由工具执行。先限制并发到可控范围；后续按供应商配额和测量结果调整，不默认给每个资产类别启动一个重复读全文的 Agent。

## 4. 工具合同

本批已注册 `production_status/read/facts/query/submit/check`。来源与产物分页合并在 status；计划目前由模型结合持久进度决策，没有单独的可编辑计划工具。

| 工具职责 | 返回与约束 |
| --- | --- |
| 列举制作来源 | 分页返回节点、阶段、集号、长度、内容版本与关联；区分正文、计划和规范。 |
| 读取正文片段 | 输入来源 ID、版本、游标；返回原文片段、位置和下一页。内容变化返回冲突，不能悄悄换成另一版。 |
| 查询共享事实 | 按主体、类别、集号、来源版本分页检索；返回证据引用和缺失范围。 |
| 提交事实批次 | 验证来源与证据，按稳定键幂等写入；结构错误返回字段级原因，让 Agent 定向修复。 |
| 查询当前产物 | 返回已有资产、生成版本、用户编辑状态和关联事实，避免重复生成。 |
| 提交制作产物 | 验证阶段、步骤、来源、目标容器及预期版本；写入文本节点、关系和执行收据。 |
| 检查制作覆盖 | 返回机器可验证的遗漏和冲突；语义遗漏另列模型审查结果，不能把“已读完”当成“无遗漏”。 |
| 更新执行计划 | 记录依赖、状态、产物引用及阻塞原因；产物不存在或校验失败时不能标完成。 |

单次工具响应使用总字节/Token 预算和分页。工具结果只把本轮必要内容交给模型；完整事实和长文产物在服务端持久保存。所选模型需要通过现有能力合同确认支持工具调用，不支持时明确提示更换，不能假装已进入 Agent 模式。

## 5. 持久化与恢复

- 作业保存目标、输入版本清单、计划、游标、事实引用、产物引用、执行收据、预算与待处理问题。
- 实际模型调用继续使用现有 Task 和账务流程；未知提交结果先核对，不能简单重发。
- 使用运行 ID、步骤 ID、输入版本与产物稳定键实现幂等。恢复时先查询收据，完成的写入和收费调用不重放。
- 关闭页面只断开观察，不停止后端执行。重新打开通过服务端作业查询和事件游标恢复。
- 暂停在安全步骤边界停止派发；已在上游执行的调用如实显示状态。继续沿用同一作业与检查点。
- 来源被修改时，建立受影响集合；旧结果保留并标记过期。由用户选择继续旧版本或重新处理变动来源，不能混合版本。
- 用户编辑的资产不能被后台旧结果覆盖；产生候选新版本或明确冲突。用户删除目标后禁止后台复活节点。
- 共享缓存至少隔离用户、项目、制作流程、来源版本、提取合同及相关模型配置；不能跨账号复用私有内容。
- 实施前确定事实/产物持久化的现有存储能否承载。如果需要新表或字段，单列迁移、文档和回退步骤；本方案不把数据库变更描述为已获本轮实施验收。

## 6. 修复循环与停止条件

可修复的工具参数或输出格式错误，返回定位信息供 Agent 修正。漏读片段、缺失资产和疑似别名冲突，通过重读相关来源再处理；不重跑全剧。

限流及暂时过载采用有上限的退避；等待期间释放 Worker。供应商提交状态不明时先查状态，已计费但无结果的情况遵循原账务恢复规则。

运行必须设置调用预算、费用上限、修复次数和无进展停止条件。达到上限时保存成果并显示停止原因。预算和权限检查由后端执行，不能交给模型自行遵守。

Agent 可以改善失败后的处理方式，但不能保证任何模型都可靠、任何供应商都可用。规划和复核会增加调用次数，效率评价需要比较完整任务的用时、成本、遗漏和人工干预次数。

## 7. 界面效果

原生成入口提交后台制作作业。保留模型与必要参数，任务面板展示：

- 当前任务及步骤，例如“读取第 7 集”“归并人物别名”“检查场景遗漏”。
- 可核对的进度，例如“已读取 7/12 集；人物已提交 9 项；场景待整理”。计划未确定前不虚构完成百分比。
- 已生成资产和待确认问题，点击可定位对应容器、节点或来源。
- 后台运行、暂停、继续、取消及失败原因。

正文容器关联各分类容器；分类资产作为容器成员管理。规划记录和共享事实在任务详情中查看，不自动生成大量画布过程节点。

## 8. 分批实施与验收

### A：跑通真实 Agent 纵向链路

打通“正文容器 -> 创建 Agent 作业 -> 分页读取 -> 保存事实 -> 人物资产逐项入容器 -> 覆盖检查”。复用现有 Agent 运行时、模型选择、任务准入和画布保存服务。页面关闭后继续执行、重新打开恢复进度作为首批验收，不能仅用对话文本证明完成。

### B：共享提取与增量修订

接入场景、道具、特殊资产和统一制作规范；验证不同分类复用同版本事实。增加单集改动后的定向更新、别名合并、冲突呈现和用户编辑保护。

### C：故障恢复与运行控制

补全暂停继续、服务重启、重复点击、回执丢失、上游过载、输出不完整、预算耗尽和节点删除的行为测试。检查任意恢复点不重复收费、不漏写、不覆盖人工内容。

### D：推广到其他制作阶段

在上述闭环验收后，用同一作业/来源/产物合同接入多集正文、跨集汇总和分镜。阶段专属规则使用独立工具和校验，不复制一套编排系统。

## 9. 对比与人工验收

使用同一份 12 集副本、相同模型配置与明确目标，分别记录现有分批方案和 Agent 方案：总耗时、实际费用、已读来源、已产出资产、已知资产漏项、错误合并、证据准确性和人工介入次数。测试夹具使用模拟供应商；真实计费调用由用户触发。

人工验收重点：人物/场景/道具清单是否完整，跨集变体是否正确，风格与规则是否有原文依据，恢复后是否重复生成，以及完成报告是否准确说明未覆盖内容。

最终交付区分“机器校验通过”“模型审查完成”和“人工确认”，不把其中任意一项替代另外两项。
